# Contributing

This handbook favors accurate, durable guidance over volume. Use a branch and pull request; run `python -m pip install -r requirements.txt` followed by `mkdocs build --strict` before requesting review.

Write sanitized, vendor-neutral examples unless a page explicitly cites official vendor documentation. Explain prerequisites, blast radius, validation, and cleanup for every operational command. Do not add credentials, real account identifiers, internal URLs, customer data, or production incident details. Link version-sensitive claims to an authoritative source.

Pages should state the objective, evidence-driven troubleshooting steps, trade-offs, and further reading. Keep navigation synchronized with `mkdocs.yml`.
